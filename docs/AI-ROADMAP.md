## Что решено

**Сервис: YandexGPT** (Yandex AI Studio).

Обоснование выбора (важно не пересматривать без причины):

1. **Юридический довод — главный.** Платформа хранит ФИО, паспортные данные,
   сканы документов, личную переписку. Передача таких данных на серверы OpenAI
   в США — риск нарушения 152-ФЗ. Для платформы, продающей доверие и
   безопасность, риск неприемлем.
2. Оплата рублями с российской карты (у OpenAI российские карты не проходят —
   потребовался бы посредник).
3. Цена ниже: Lite ~0,20 ₽ / 1000 токенов, Pro ~0,80 ₽.
4. OpenAI-совместимый API — смена сервиса в будущем потребует минимальных правок.

Компромисс: качество ответов у OpenAI выше, но для наших задач (черновики,
модерация, перевод, типовые ответы) YandexGPT достаточно.

**Требуемые секреты:** `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` — запрошены у
владельца, на момент записи не заполнены.

## Очередь внедрения

Порядок продуман: от безопасного к рискованному по расходам.

### 1. Помощник в заполнении профиля (первый)
Составляет черновик описания и списка услуг за специалиста на основе его
специализации, лицензий и тегов. Человек проверяет и правит перед сохранением.

- Зачем: профили заполняются полнее → каталог выглядит солиднее → выше конверсия.
- Почему первым: работает только для авторизованных специалистов, расходы
  предсказуемы, злоупотребить нельзя.
- Файлы: `backend/save-verification/`, `src/components/ProviderDashboard.tsx`.

### 2. Умная модерация переписки и отзывов
Распознаёт угрозы, скам, попытки увести оплату мимо платформы — по смыслу,
а не по словарю запрещённых слов (сейчас в `backend/messages/index.py`
используется список корней BAD_ROOTS).

- Зачем: защита клиентов от мошенников, снижение ручной модерации.
- Почему второй: фоновая обработка, объём ограничен реальным трафиком.
- Важно: ИИ только помечает подозрительное, окончательное решение о блокировке
  оставить за администратором.

### 3. Автоперевод профилей на 7 языков
Описания и услуги специалистов переводятся на все языки сайта
(RU, EN, FR, DE, JA, AR, HE).

- Зачем: платформа заявлена как международная, но профили пишутся на одном языке.
- Почему третий: фоновая задача, результат сохраняется в БД один раз — расходы
  разовые на каждый профиль.
- Файлы: `backend/translate/` (уже есть функция перевода), `src/lib/i18n.tsx`.

### 4. Помощник-консультант для клиентов (последний)
Чат-бот отвечает на вопросы: какой специалист нужен, сколько стоит,
как проверить лицензию.

- Зачем: удерживает посетителей, снимает нагрузку с владельца.
- **Почему последним — риск расходов.** Функция публичная: любой посетитель
  тратит деньги владельца. Один назойливый бот способен за ночь сжечь бюджет.
- **Обязательно заложить до запуска:**
  - лимит обращений с одного IP (переиспользовать `backend/*/rate_limit.py`);
  - дневной потолок расходов с автоотключением при достижении;
  - ограничение длины запроса и ответа;
  - учёт расхода токенов в БД для контроля счёта.

## Идеи на будущее (обсудить, не согласовано)

Отсортированы по соотношению пользы и риска.

### Высокая польза

- **Умный подбор специалиста по заявке.** Клиент описывает задачу своими
  словами («пропал человек, нужно найти»), ИИ определяет категорию и предлагает
  подходящих исполнителей с учётом города и рейтинга. Сейчас категорию клиент
  выбирает вручную, а уведомления уходят всем специалистам категории веером.
  Прямо влияет на выручку: меньше клиентов уходит, не найдя нужного человека.
  Файлы: `backend/requests/index.py`.

- **Приоритетное оповещение по заявке.** Вместо рассылки всем — определить
  топ-3 наиболее подходящих специалиста и уведомить их первыми. Снижает
  «шум» для специалистов и ускоряет отклик для клиента.

- **Черновик кейса из завершённой заявки.** После закрытия задачи предложить
  специалисту готовый черновик кейса для портфолио. Сейчас связи между
  выполненными заявками и портфолио нет вообще.
  Файлы: `backend/provider-cases/`, `backend/requests/`.

- **Помощь клиенту в описании задачи.** Многие не знают, что писать. ИИ задаёт
  уточняющие вопросы и помогает составить внятное ТЗ → специалисты получают
  качественные заявки и охотнее откликаются.

### Средняя польза

- **Краткая выжимка отзывов** в карточке специалиста («чаще всего отмечают:
  оперативность, детальные отчёты»). Экономит время клиента при выборе.

- **Подсказка цены специалисту** на основе категории, города и рынка —
  помогает новичкам не занижать и не завышать стоимость.

- **Ответы на типовые вопросы в переписке** — черновик ответа для специалиста,
  чтобы быстрее реагировать на обращения клиентов.

- **SEO-описания для страниц услуг и городов** — генерация текстов под
  поисковые запросы, рост бесплатного трафика.

### Требует осторожности

- **Помощь в проверке документов (OCR).** Извлечение реквизитов из сканов
  лицензий для ускорения работы администратора.
  **Строгое ограничение: ИИ только подсказывает, решение принимает человек.**
  Верификация — основа доверия к платформе, цена ошибки ИИ здесь выше любой
  экономии времени. Автоматическое одобрение профилей не делать никогда.

- **Выявление подозрительных профилей** — признаки накрутки отзывов,
  дублирующиеся профили, несоответствие услуг заявленной специализации.
  Тоже только как сигнал администратору.

### Отклонено

- **Полностью автоматическая верификация специалистов** — недопустимо.
  Обосновано выше: цена ошибки несоизмерима с выгодой.

## Общие правила для всех ИИ-функций

1. **Персональные данные не отправлять в ИИ без необходимости.** Паспортные
   данные, номера документов, контакты — исключать из запросов. Для модерации
   и перевода передавать только текст, который и так публичен либо обезличен.
2. **Лимиты расходов обязательны** для любой функции, доступной посетителям
   без авторизации.
3. **ИИ не принимает окончательных решений** о блокировках, верификации и
   деньгах — только готовит рекомендацию для человека.
4. **Отказ ИИ не должен ломать сайт.** Если сервис недоступен или закончились
   средства — функция тихо отключается, основной сценарий продолжает работать.
5. **Ответ ИИ — не доверенные данные.** Экранировать перед выводом на страницу,
   как любой пользовательский ввод (защита от XSS).

## Незакрытый вопрос по безопасности (не про ИИ)

Токен входа хранится в localStorage и доступен скриптам. Полностью закрывается
только переносом cloud-функций на поддомен `api.shieldpspl.ru` (тогда возможна
HttpOnly-cookie). Обращение в поддержку платформы подготовлено, ожидается ответ.
Запасной вариант при отказе: хранение токена в памяти вкладки с тихим
обновлением сессии.
